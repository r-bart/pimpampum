Desktop surfaces

Design handoff for the macOS menu-bar indicator and Omarchy Quattro widget. One daemon, two surfaces, closed scope.

This document is the implementation reference. All interface copy is English and transcribed verbatim. Values supplied by the operating system or active Quattro theme are identified and must not be replaced with custom values. The interactive mockup contains the rendered states; this document contains the rules.

01 · Information model

An unexpired claim is the only representation of work in progress. There is no persisted Doing state: when the claim expires, the row disappears. The section is always named Active work.

The compact count is always the number of unexpired claims, never projects or tasks. Hide it at zero.

Global precedence

When several conditions apply, render the first match in this order: connection, credentials, schema, or payload error; active claims; available work without active claims; drafts only; all complete; no projects.

A project may have active and available work at once: its primary state is Active and both counts remain visible. Incomplete projects come first, ordered Active → Available → Draft. Completed projects never mix into that list.

02 · Approved compact mark

The approved variant C mark is one exact 16 × 16 pt circle containing a lowercase p. Its silhouette stays fixed in every compact state on macOS and Quattro. It is a monochrome template icon that inherits the system or active-theme foreground color.

approved decision · final

Variant C is final and in use. Variants A and B are rejected explorations. State is expressed outside the fixed circle-and-lowercase-p mark through a 5 pt badge or accent, semantic color, count, tooltip, and detailed copy.

Mark rules

  • Never replace the mark. Offline does not turn the app into a Wi-Fi, cloud, database, or generic-warning icon.
  • Express state with an adjacent 5 pt badge, semantic color, count, tooltip, and detailed copy inside the popover.
  • Place the count beside the mark, never inside the logo. Use a 4 pt separation.
  • Keep it legible on light and dark backgrounds in one tint.
  • Deliverables: mark vector, monochrome macOS template variant, light and dark treatments, and horizontal and vertical Quattro variants.

Active-claim count

Hidden at zero. Use tabular or monospaced digits. Show one and two digits directly; cap at 99+ rather than growing beyond available space. It is visually secondary to the mark but clearly legible. In stale state, retain the count only if it stays clearly secondary in tertiary color; otherwise hide it.

03 · macOS · menu bar

Native MenuBarExtra with no Dock icon. Use standard menu-bar height, alignment, and click area. Content is the fixed mark plus optional count. Neither “Pimpampum” nor any permanent status word appears in the bar.

Tooltip and accessibility label: Pimpampum: {status label}, {N active claims}. Singular: 1 active claim; plural and zero: {N} active claims. Icon and count form one accessibility element. Clicking toggles the popover.

Fixed: header; connection, credentials, or incompatibility notice; login-approval notice; Summary; Active work; Projects; Completed disclosure; truncation and folder-opening errors beside their source content; footer with Quit and Settings. Login approval

Show only when macOS requires explicit login-item approval. Use a compact amber-tinted container, system security icon, title Login approval required, body Allow Pimpampum in Login Items to start it automatically., and action Open Login Items Settings. This is unrelated to automatic backup.

Summary

Use the SUMMARY micro-uppercase label. Primary line: {projects} projects · {active claims} active · {available work} available; secondary line: Daemon {version} · {uptime} uptime. Show uptime in seconds below one minute, in minutes below one hour, then as Nh or Nh Nm. Treat both lines as one accessibility element.

Active work

Use the ACTIVE WORK label. When empty, show No active work in a secondary subheadline. Otherwise, render one compact row per unexpired claim, with no actions.

Row content, in order: work title in medium subheadline, maximum two lines; for task claims, project title below in a one-line secondary caption; agent ID with person icon; remaining lease with timer icon. Keep agent and timer on one line, separated by ~10 pt. Use 10 pt padding, 8 pt radius, and the system quaternary background. Treat the whole row as one accessibility element.

Lease copy: Expired · <1m remaining · Nm remaining · Nh remaining · Nh Nm remaining. If the API truncates, show Active work is truncated. Refine the project set to see more. as informational text, not a button.

Projects

Each row is a full-width plain button that opens the workspace root in Finder. Content: fixed-width 16 pt semantic marker; project title in medium subheadline, maximum two lines; {workspace name} · {project slug} in a one-line secondary caption; status and counts in caption-2; and a discreet external-open affordance at the end.

Hover highlights the whole row with the subtle native treatment and changes the pointer. Click, Enter, and Space open the registered workspace root, never a guessed subdirectory. Accessibility label: Open {project title} in Finder; hint: Opens workspace {workspace name}.

If Finder cannot open the path, keep the project visible and show an inline error after the section: title Workspace could not be opened, detail {project title}: {sanitized error}. No modal. If the list is truncated, show The project list is truncated. Counts still include every project.

Completed, empty states, and footer

The Completed ({N}) disclosure is collapsed on every launch and omitted when the count is zero; expansion lasts only for the session. Hint: “Collapsed by default. Expand to show completed projects.” Expanded rows reuse the same component and Finder interaction.

Without a valid overview, replace Summary, Active work, and Projects with the title Status unavailable and body No project data is shown until a compatible authenticated overview is available. With a valid overview but no projects, show the normal header and Summary, No active work, and No projects yet. No illustration or large onboarding card.

Fixed footer below the scrolling body: Quit Pimpampum on the left and Settings… with a gear on the right, both native plain buttons. Quit terminates only the menu bar app and does not delete data. Settings opens or focuses one real window and must work without a Dock icon; repeated presses focus the same window.

05 · macOS · settings window

Standard titled utility window with native traffic lights. Title: Pimpampum Settings. One instance; reopening focuses it. Initial content is 460 × 270 pt excluding the title bar, with 24 pt padding. A fixed compact layout is acceptable, but the window grows vertically before clipping when accessible text sizes or localized errors need more room. V1 has no sidebar, toolbar, tabs, or General/Advanced sections; Backup is the only page.

Header: Backup in semibold title-2, description Keep one current snapshot after every change. The live database stays local. in a secondary subheadline, and a borderless icon button with tooltip and label Refresh backup status, disabled while an operation is in flight. No cloud-provider logos: the destination may be local, Dropbox, Drive, iCloud, or any synchronized folder.

Configured-state information order: FOLDER label; full absolute path in selectable monospace, maximum two visual lines; Change… and Open in Finder; health row; primary operational action; and destructive Disable action.

Folder selection: Choose Folder… and Change… open exactly one native directory-only NSOpenPanel, with no file selection or creation. When changing an existing destination, initialize the picker there when possible. Cancel changes nothing. Confirm sends the folder to the daemon and immediately enters Pending; the UI does not declare success until the daemon confirms.

Client, installation-receipt, authentication, invalid-folder, and Finder-opening errors appear as one compact inline error below the primary content: warning icon and selectable semantic-red text with enough wrapping to remain actionable. No sheets or alerts for routine errors. Never show credentials or raw payloads. Reference copy: Pimpampum's installation receipt could not be read. Run pimpampum install. · Choose another folder. · Pimpampum rejected the local token. Run pimpampum install to reconcile it. · Finder could not open the backup directory: {path}.

Disable uses the native destructive role and has no confirmation in v1 because disabling does not delete the existing snapshot. On success, enter Disabled; on failure, retain the configured state and show the inline error.

06 · Quattro · bar widget

Native Quickshell bar-widget plugin for horizontal and vertical bars. Inherit foreground, background, urgent color, font family, position, and bar size. Do not draw a custom background panel except for Quattro's standard hover or active treatment. Hot reload must not leave duplicate popouts.

Horizontal: vertically center the mark and optional count in the inherited bar size, with ~4 theme units between them and ~12 units of total horizontal breathing room. The count uses the bar's small-body size in semibold or bold, with tabular digits when the inherited font supports them. Vertical: stack and horizontally center the mark and count while respecting the inherited width; hide the count at zero, and make the click area equal the widget bounds.

Use the same semantics and precedence as macOS. State treatment may be an adjacent dot, ring, corner badge, or color accent, provided it remains legible at the actual bar size. On hover, show the native Quattro tooltip with the full label; with cached data after a failure, show Stale · {last known status}. Click toggles the popout and uses a pointer cursor.

07 · Quattro · status popout

Native PopupCard anchored to the widget. Target content width is 380 theme units; maximum height is the smaller of 520 units and the available screen height. The body scrolls with clipped, bounded content. The bar owns popout switching so Pimpampum does not create competing popups. Inherit background, foreground, urgent color, font, radii, and spacing from the theme when available.

Order: title and connection state; connection or opening error; empty or configuration instruction; Active work; incomplete projects; Completed disclosure; Backup disclosure. The popout may omit the version and uptime block when space is tight, but never active work, projects, connection state, or backup.

Header: Pimpampum in the inherited subtitle size and bold, with the connection label beside it: online, offline, credentials, invalid, or incompatible. Use normal foreground when online, urgent color otherwise, and Stale when showing cached data after a failure. Place the wrapping connection error below in urgent body-small text. Required copy for rejected credentials: Local credentials were rejected. Run pimpampum install to repair them. Never show the token or raw stderr.

Empty states: without workspaces, show No workspaces. Run: pimpampum workspace:add; with workspaces but no projects, show No projects. Use ordinary body text with no illustration.

Active work: show the Active work ({N}) heading only when work exists. Each item shows {project title} for a project claim or {project title} — {task title} for a task claim, with {agent ID} · {remaining lease} on the secondary line. End-elide the primary text; the lease may use Quattro's compact copy: seconds below one minute, then minutes rounded up. No row actions. If truncated, show Active work list truncated in an urgent caption.

Projects: use the Projects ({N}) heading for incomplete projects. Each row shows {project title} · {status} with {workspace name} / {slug} · {N} active · {N} available below. The whole row is clickable and opens the exact workspace root in the system file explorer, with a pointer cursor and inherited hover. If the workspace is missing or cannot open, keep the row and show Could not open the workspace directory. If truncated, show Project list truncated. Completed projects use a clearly chevroned Completed ({N}) disclosure, collapsed by default and omitted at zero; expanded rows show {project title} · {workspace name} / {slug} and open the workspace root.

Popout Backup section

Use the Backup label with a chevron, collapsed by default and placed after projects so administration does not dominate operational status. Expanding it refreshes the daemon's canonical setting.

Expanded order: center-elided configured path when enabled; health label and last-success time; state or operation error when present; manual absolute-path label and field; available buttons; and picker-fallback explanation when applicable.

Field: label Backup folder (absolute path), placeholder /home/you/Dropbox/Pimpampum, one horizontally clipped line, mouse- and keyboard-editable, 28–30 units high. Enter saves only when the value is syntactically absolute; disable the field while an operation is in flight. The daemon remains the final validator: the UI does not declare success from local validation.

Buttons, in order: Choose…, visible only when Qt's optional FolderDialog is available; Save, enabled only with an absolute path; Open, Back Up Now, and Disable, enabled only when backup is configured, with urgent but not oversized treatment for the last action. During activity, disable everything with reduced emphasis, show Updating… for health, and never run two helper processes in parallel. Without FolderDialog, show Folder picker unavailable; enter an absolute path above.

Health: neutral Automatic backup is off; neutral or amber Backup pending; green Up to date, with · {localized time} when available; urgent Backup needs attention. Place bounded, sanitized, wrapping operation errors below the health label in an urgent caption; do not reserve space for raw logs.

08 · Backup: one source of truth

Automatic backup writes one rolling file named pimpampum-latest.sqlite. The live database remains local. Disabling automatic backup does not delete the existing snapshot. The daemon owns one destination: there are no per-project backup settings, history, retention, restore UI, or provider accounts. A backup failure does not imply project-data loss; avoid catastrophic language unless the server explicitly reports loss.

09 · Refresh and freshness

Overview: refresh immediately when the integration starts and when the popover or popout opens; every ~5 s while open and every ~10 s while closed. If a later request fails, retain the last valid overview in memory and mark it explicitly as stale. Claims disappear when they expire, including between server refreshes when possible.

Backup: refresh when the window or disclosure opens and after configuring, retrying, or disabling. macOS provides an explicit refresh icon; Quattro refreshes while the popout is open. During an operation, keep the last known destination visible and disable competing actions. No pull-to-refresh, progress bar, toasts, or success celebration.

Motion: no decorative animation. Loading uses the platform spinner or progress indicator; disclosures use the default transition; state changes may use a subtle crossfade when the platform provides one naturally. Respect reduced-motion settings.

10 · Typography, color, and spacing

On macOS, use native semantic styles rather than fixed sizes: semibold title-2 for the window title; headline for the popover title; semibold uppercase caption in secondary color for section headings; medium subheadline for primary row text; secondary caption for supporting text; secondary caption-2 for tertiary metadata; and monospaced body for paths. Use system semantic colors—primary, secondary, tertiary, quaternary, red, orange/amber, blue, and green—rather than hard-coded light-mode grays.

On Quattro, use the active theme tokens: bar.foreground, bar.background, bar.urgent, bar.fontFamily, bar.barSize, Style.font.*, and Style.space(*). Introduce blue, amber, and green accents only when the theme has no equivalent token, and verify them in light and dark themes.

11 · Copy rules and content limits

  • All interface copy is English and sentence case, except macOS micro-uppercase section labels.
  • Use an ellipsis … only for actions that open another interface before completion: Settings…, Choose Folder…, Choose…, and Change…. Back Up Now and Disable act immediately and have no ellipsis.
  • Always show Quit Pimpampum explicitly; never use an unlabeled power icon.
  • Say Active work, never Doing; and available, never todo or backlog.
  • Never show raw IDs, token paths, database paths, PRD text, task bodies, artifacts, error stacks, or JSON.

Limits: project titles allow two lines on macOS and one end-elided line in compact Quattro rows. With duplicate titles, keep the workspace name and slug visible for disambiguation, end-elided on one line if needed. Agent IDs occupy one line and retain enough text to distinguish agents. Completed-task counts may be large but never displace the external-open affordance.

Paths may contain spaces, Unicode, quotes, and shell metacharacters and are treated only as text. On one line, prefer center elision so the root and final folder remain visible; in macOS settings, paths may wrap to two lines and must be selectable. Never design shell-escaping affordances or command previews. Counts are non-negative integers: popover detail may show the full value, while the compact count caps at 99+ when width requires it. Connection-error detail occupies at most three visible lines; settings and backup errors may wrap enough to remain actionable; Quattro errors remain compact and bounded, with no scrolling log area.

12 · Accessibility and keyboard

  • Provide full keyboard navigation in visual order with native focus rings. Enter and Space activate the focused button. Escape closes the folder picker, not the settings window unless the platform does so by default.
  • Every icon-only action has a tooltip and accessibility label. Combine the state icon and its text into one meaningful element.
  • Menu bar: Pimpampum: {status label}, {N active claims}. Project rows: Open {project title} in Finder with hint Opens workspace {workspace name}. Completed disclosure: Collapsed by default. Expand to show completed projects. Quattro widget: {N} active claims.
  • Support VoiceOver and increased contrast. Do not rely on red and green; accompany every color with a shape or text.
  • On Quattro, every clickable row or button has visible hover and focus; keyboard activation mirrors pointer activation where Quickshell permits; text and controls meet the active theme's accessible contrast; and no custom pointer gestures block scrolling.

13 · Out of scope in v1

If a control or section does not appear in this document, it must not appear in the design. Specifically excluded: creating or editing projects, PRDs, context documents, tasks, or subtasks; claiming, renewing, releasing, or completing work; a persisted Doing state; starting, stopping, or restarting the daemon from these surfaces; logs, terminal output, a diagnostics browser, or database inspection; notifications; search, filters, sorting, tabs, sidebar, or command palette; per-project backup settings; history, retention, restore, or provider accounts; preferences unrelated to backup; analytics or charts; a Dock icon or ordinary application window on macOS; and Waybar support, because Linux targets only Omarchy Quattro/Quickshell.

14 · Acceptance checklist

Identity

  • The fixed Pimpampum mark remains visible in every compact state.
  • Offline is not represented by replacing the mark with a Wi-Fi icon.
  • The count is legible and hidden at zero.
  • Every semantic color is accompanied by text or a distinct shape.

macOS

  • The menu bar app has no Dock presence.
  • The popover is 360 pt wide with fixed header and footer and a scrolling body.
  • Active work and project data follow the described hierarchy exactly.
  • Completed projects are collapsed by default.
  • Project rows clearly indicate that they open Finder and show disambiguation.
  • Cached data is clearly marked as stale.
  • The footer contains Quit Pimpampum and Settings….
  • Settings opens or focuses one real window.
  • The backup window covers loading, disabled, pending, healthy, and error.
  • Folder selection is native and directory-only.
  • Errors are inline and actionable.

Quattro

  • The widget works in horizontal and vertical bar geometry.
  • The widget inherits the active Quattro theme tokens.
  • The popout uses native PopupCard behavior and remains bounded and scrollable.
  • Active work, projects, Completed disclosure, and backup appear in the required order.
  • Workspace rows clearly indicate that they open the system file explorer.
  • Backup remains collapsed by default.
  • Both the folder dialog and manual absolute-path fallback are designed.
  • In-flight operations disable competing actions.
  • No token, raw stderr, or shell command appears in the interface.

Scope

  • No project, task, or PRD editing controls have been added.
  • No Doing lifecycle state appears.
  • No daemon lifecycle controls have been added.
  • No backup history, restore flow, or account interface has been added.
  • No additional navigation or settings categories have been added.
